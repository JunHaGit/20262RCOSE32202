## Project #1 — 시스템 콜을 이용한 커널 스택 구현

### 프로젝트 개요

Linux 커널에 정수 스택을 관리하는 시스템 콜을 추가하고, 사용자 프로그램에서 호출하여 동작을 확인한 프로젝트입니다. 사용자 프로그램의 요청이 커널에서 처리되고 결과가 반환되는 과정을 실습했습니다.

### 구현한 기능

- **push**: 정수를 스택의 맨 위에 추가합니다.
- **pop**: 스택의 맨 위 항목을 제거하고 저장된 정수를 반환합니다.
- **clear**: 스택의 모든 항목을 제거하고 제거한 개수를 반환합니다.

스택은 연결 리스트로 구성하여 가장 나중에 넣은 값이 먼저 나오는 LIFO 방식으로 동작하도록 구현했습니다. 공유 스택에 대한 접근은 공통 뮤텍스로 보호했습니다.

이 저장소에는 과제 안내에 따라 프로젝트 소스 코드 대신 구현 내용과 학습 내용을 정리합니다.

### 개발 환경

| 항목 | 사용 환경 |
|---|---|
| 호스트 운영체제 | Windows 11 |
| Linux 실행 환경 | WSL2 |
| 배포판 | Ubuntu 22.04.5 LTS |
| 실습 커널 | 6.6.36.3OS+ |

WSL2 환경에서 수정한 커널을 빌드하고 사용자 테스트 프로그램을 실행했습니다. 커널 구현과 사용자 프로그램을 구분하여 작업하고, 실행 결과와 커널 로그를 함께 확인했습니다.

### 사용자 모드와 시스템 콜

사용자 프로그램은 사용자 모드에서 실행되며, 보호된 커널 자원에 직접 접근할 수 없습니다. 시스템 콜은 사용자 프로그램이 커널에 필요한 서비스를 요청하는 인터페이스입니다.

이번 프로젝트에서는 범용 호출 함수인 syscall을 통해 시스템 콜 번호와 인자를 전달했습니다. 요청이 커널에 진입하면 번호에 대응하는 처리 루틴이 실행되고, 처리 결과가 사용자 프로그램으로 반환됩니다.

호출 흐름은 다음과 같습니다.

1. 사용자 프로그램이 시스템 콜 번호와 인자를 전달합니다.
2. CPU가 커널 모드로 전환하여 요청을 처리합니다.
3. 커널이 번호에 해당하는 스택 연산을 수행합니다.
4. 반환값을 전달하고 사용자 모드로 복귀합니다.

이 과정의 모드 전환은 다른 프로세스로 실행이 넘어가는 문맥 교환과 구분됩니다.

### 시스템 콜 등록과 빌드 반영

스택 연산의 구현뿐 아니라, 사용자 프로그램에서 해당 기능을 호출할 수 있도록 커널의 등록 정보와 빌드 설정을 수정했습니다.

| 수정 대상 | 역할 |
|---|---|
| 시스템 콜 테이블 | 실습 환경에서 335번은 push, 336번은 pop, 337번은 clear에 연결 |
| 시스템 콜 선언 헤더 | 추가한 세 연산의 반환 타입과 인자 정보 선언 |
| 커널 구현 파일 | 스택의 상태와 각 연산의 처리 동작 구현 |
| 커널 Makefile | 구현 파일의 오브젝트를 커널 빌드에 포함 |

사용자 프로그램에서도 커널 테이블에 등록한 번호와 동일한 번호를 사용했습니다. 위 번호는 이번 실습 환경에서 사용한 값입니다. 등록 정보, 선언, 구현, 빌드 설정이 함께 연결되어야 새 기능이 커널에 반영됩니다.

### 스택 구조와 연산 방식

스택은 정수 값과 다음 노드의 위치를 저장하는 노드를 연결하여 구성했습니다. 맨 위 노드를 가리키는 포인터로 스택에 접근하며, 가리키는 노드가 없으면 빈 스택입니다. 스택 상태는 커널의 전역 상태로 유지됩니다.

- **push**: 새 노드를 만들고 기존 맨 위 노드를 그 아래에 연결한 뒤, 새 노드를 스택의 맨 위로 지정합니다.
- **pop**: 맨 위 노드의 값을 보관하고 스택의 시작점을 다음 노드로 옮긴 뒤, 제거한 노드의 메모리를 해제합니다.
- **clear**: 노드를 순서대로 제거하면서 메모리를 해제하고, 제거한 개수를 반환합니다.

pop에서 가장 최근에 추가한 값을 먼저 꺼내므로 LIFO 순서가 유지됩니다. 노드의 값을 메모리 해제 전에 보관하여 해제된 메모리를 읽지 않도록 했습니다.

### 공유 스택과 동기화

커널에 유지되는 스택은 여러 프로세스가 시스템 콜을 통해 접근할 수 있는 공유 상태입니다. 두 실행 흐름이 동시에 같은 노드를 제거하면, 이미 해제된 메모리에 접근하거나 같은 노드를 다시 해제하는 문제가 생길 수 있습니다.

이를 방지하기 위해 push, pop, clear가 동일한 뮤텍스를 사용하도록 했습니다. 각 연산은 잠금을 획득한 상태에서 공유 스택을 확인하고 변경한 뒤 잠금을 해제합니다. 스택 상태를 로그로 출력할 때도 잠금을 유지하여 순회 중 노드가 변경되거나 해제되지 않도록 했습니다.

이번 실행 결과는 단일 사용자 프로그램의 순차 호출을 검증한 것입니다. 여러 프로세스의 동시 접근에 대한 별도 실험은 수행하지 않았습니다.
